# Data Model

The PostgreSQL schema, module by module. Every module owns one schema and is the only code that writes to it (see [architecture.md §4](architecture.md#4-module-responsibilities-and-seams)). Read-only dashboard queries in the Admin module may join across schemas through SQL views that the owning modules define.

## Conventions

- PKs are `id uuid` (UUIDv7, generated by the application). FKs are `<entity>_id`.
- Timestamps are `timestamptz` and stored in UTC, with names ending in `_at`. Durations are `integer` milliseconds with names ending in `_ms`.
- Money is `numeric(20,10)` plus `currency char(3)`. Per-million-token prices are `numeric(20,10)`. The MVP accepts only `USD`; the `currency` columns exist so multi-currency can be added later.
- Enumerations are `text` with a `CHECK` constraint, not PG enums, so adding a value is a plain migration.
- `jsonb` is used only for: Capabilities, Routing Policy definitions, Routing Decision details, evaluation inputs/outputs/scoring config. Anything the dashboard filters or groups by is a real column.
- Soft state changes such as revocation, disabling and suspension are columns. Rows that history points to are never deleted while that history is retained.

## Deviations from PRD §7

| PRD | Here | Why |
|---|---|---|
| `Model.Alias` | `routing.model_alias` → policy | One alias can span several Provider Models (ADR-0008) |
| `Model.*PricePerMillionTokens`, `PricingVersion` | `registry.model_price` rows | Prices are immutable and versioned (FR-06) |
| `ProviderAttempt.InputTokens/OutputTokens/EstimatedCost` | Kept as a denormalized copy; `usage.usage_record` is authoritative | Fast timeline rendering. Usage Records hold provenance |
| `InferenceRequest.SelectedModelId` | Kept, plus `routing_decision jsonb` | FR-04 asks for the selection reason |
| `EvaluationRun.ModelConfiguration` | `run_configuration jsonb` + `comparison_id` | Several runs are grouped into one Comparison |
| (not present) | `api_key.name`, `tenant_limits`, `budget_period`, `reservation`, `outbox_event`, `processed_event`, `job`, `audit_record`, `administrator`, `prompt`, `prompt_version`, `dataset_version`, `usage_hourly`, `provider_secret`, `provider_health_snapshot`, `config_version` | PRD §7 allows additional tables |

## `identity`

**tenant**: `id`, `name text unique`, `status text check (active|suspended)`, `created_at`, `updated_at`

**tenant_limits** (1:1 with tenant): `tenant_id pk fk`, `requests_per_minute int null`, `max_concurrent int null`, `max_request_cost numeric null`, `allowed_aliases text[] not null default '{*}'`, `updated_at`. A NULL limit means unlimited. The `budget_amount` and `budget_period` columns from the first migration are unused: the Budget lives only in `usage.budget`.

**api_key**: `id`, `tenant_id fk`, `name text`, `key_prefix char(8) unique`, `key_hash bytea(32)`, `scopes text[]`, `expires_at null`, `revoked_at null`, `last_used_at null` (updated at most once per minute), `created_at`, `created_by_admin_id`
- Index: `unique(key_prefix)`, `(tenant_id, created_at desc)`

**administrator**: a minimal custom store (not the `AspNetUsers` table set) that uses ASP.NET Core Identity's `PasswordHasher<T>` (PBKDF2): `id`, `email` (unique, lower-case), `password_hash`, `role text check (owner|operator|viewer)`, `all_tenants bool` (Owner implies true), `active bool`, `failed_sign_in_count`, `failed_sign_in_window_started_at`, `locked_until`, `last_signed_in_at`, `created_at`, `updated_at`.

**administrator_tenant_grant**: `administrator_id`, `tenant_id`, pk both.

**administrator_session**: `id` (SHA-256 of the cookie's session key, base64url), `administrator_id fk`, `created_at`, `expires_at` (sliding 8 h), `absolute_expires_at` (24 h). Deleted on sign-out and deactivation; an expired session is deleted when its Administrator next signs in, and by the daily retention run otherwise (see Retention).

**data_protection_key**: `id`, `friendly_name`, `xml`, `created_at`. The ASP.NET Core Data Protection key ring, shared by all api instances (cookie and antiforgery protection).

**audit_record**: `id`, `occurred_at`, `administrator_id`, `action text` (e.g. `api_key.created`, `provider.secret_replaced`, `routing_policy.versioned`), `tenant_id null`, `target_type`, `target_id`, `details jsonb` (`before`/`after` summaries and extra keys; never secrets or content), `source_ip inet`, `request_id uuid null`, `trace_id text`
- Append-only. The application DB role has no `UPDATE`/`DELETE` grant on this table.
- Index: `(occurred_at desc)`, `(tenant_id, occurred_at desc)`

## `registry`

**provider**: `id`, `name unique`, `adapter_type text check (openai_compatible|ollama)`, `endpoint text`, `credential_reference text null` (`env:NAME` or `db:<uuid>`), `request_timeout_ms int`, `enabled bool`, `created_at`, `updated_at`

**provider_secret**: `id`, `provider_id`, `ciphertext bytea`, `nonce bytea(12)`, `tag bytea(16)`, `key_version smallint`, `created_at` (ADR-0007)

**provider_model**: `id`, `provider_id fk`, `provider_model_id text`, `display_name`, `capabilities jsonb`, `enabled bool`, `created_at`, `updated_at`
- `unique(provider_id, provider_model_id)`
- `capabilities` shape: `{ "streaming": true, "jsonObject": true, "jsonSchema": false, "contextWindow": 128000, "maxOutputTokens": 16384, "parameters": ["temperature","top_p","seed","stop"], "tokenizer": "o200k_base" }`

**model_price**: `id`, `provider_model_id fk`, `input_per_million numeric`, `cached_input_per_million numeric null` (null = no discount: cached tokens cost the input rate; `0` = free), `output_per_million numeric`, `currency`, `effective_from timestamptz`, `created_at`, `created_by_admin_id`
- `unique(provider_model_id, effective_from)`. No updates. The price in force is the row with the latest `effective_from ≤ now`.

**provider_health_snapshot**: `instance_id text`, `provider_model_id`, `circuit_state text`, `window_failure_rate real`, `window_calls int`, `captured_at`. pk `(instance_id, provider_model_id)`, upserted every 15 s.

## `routing`

**routing_policy**: `id`, `name unique`, `latest_version int`, `created_at`

**routing_policy_version**: `policy_id`, `version int`, `definition jsonb`, `resolved_candidates jsonb` (authored `provider/model` name to Provider Model id, fixed when the version is saved), `created_at`, `created_by_admin_id`, pk `(policy_id, version)`. Immutable: the app role has no `UPDATE`/`DELETE` grant. The `definition` schema is in [routing-and-resilience.md](routing-and-resilience.md#2-routing-policy-definition).

**model_alias**: `alias text pk` (`[a-z0-9][a-z0-9._-]{0,63}`), `policy_id fk`, `description`, `updated_at`. An alias always resolves to the policy's **latest** version at request time. The Policy Version actually used is recorded on the request.

## `config`

Owned by `ModelSwitch.Configuration` (infrastructure, not a domain module), created by plain idempotent DDL in the Migrator rather than an EF Core migration. The app role gets the usual table grants.

**config_version**: a single row (`id boolean pk default true check (id)`, `version bigint`, starts at 0). Incremented in the same transaction as any write to runtime configuration, followed by `NOTIFY config_changed`.

| total_input_tokens, total_output_tokens | int null | sum over Attempts |

Indexes: `(tenant_id, started_at desc)`, `(started_at desc)`, `(status, started_at desc) where status <> 'succeeded'`, `(selected_provider_model_id, started_at desc)`, `(requested_alias, started_at desc)`, `(evaluation_run_id) where evaluation_run_id is not null` (a run's Estimated Cost so far, `IEvaluationRunCost`). Every index is declared on the partitioned parent, so PostgreSQL builds it on each existing partition and on every partition created later. Partitioned by month on `started_at` (declarative range partitioning), so retention can drop whole partitions.

**provider_attempt**: `id`, `inference_request_id`, `attempt_number smallint`, `provider_id`, `provider_model_id`, `kind text (primary|retry|fallback)`, `status text (succeeded|failed|cancelled|ambiguous|skipped_circuit_open)`, `error_class text null (transient|permanent|ambiguous)`, `error_code null`, `http_status smallint null`, `provider_error_type text null` (sanitized, ≤64 chars), `started_at`, `completed_at`, `duration_ms`, `ttft_ms null`, `input_tokens null`, `output_tokens null`, `estimated_cost null`
- `unique(inference_request_id, attempt_number, started_at)`: a unique index on a partitioned table must include the partition key, and `started_at` is the Attempt's own. Index on `inference_request_id`. Partitioned like `inference_request`.

**Partitioning.** Both tables are `PARTITION BY RANGE (started_at)` with one partition per UTC month, named `<table>_yYYYYmMM`. EF Core cannot create partitioned tables, so the `usage` migration creates them with raw SQL; the primary keys are `(id, started_at)` for the same reason. There are no foreign keys between the two tables (PostgreSQL cannot reference a partitioned table without its partition key, and retention drops partitions independently). The migration also creates `usage.ensure_request_partitions(months_back, months_ahead)`, which idempotently creates the missing monthly partitions. The Migrator calls it on every run (previous month through 12 months ahead), so partitions exist as long as the system is deployed at least yearly. There is no `DEFAULT` partition, because a later `CREATE ... PARTITION OF` fails once the default holds rows in that range. The retention job (below) also maintains them through `usage.maintain_request_partitions(retention_days, months_ahead)`, a `SECURITY DEFINER` function owned by the migrator role with a fixed `search_path`: it calls `ensure_request_partitions(0, months_ahead)`, then drops each partition whose whole UTC month ended before `now() - retention_days`, skipping (until the next run) any partition whose lock it cannot get within 5 s, and returns the names it dropped. `EXECUTE` on both functions is revoked from `PUBLIC`; the Migrator grants `maintain_request_partitions` to `modelswitch_retention` and also to `modelswitch_app`, because without `ConnectionStrings:PostgresRetention` the worker runs retention as the app role and must still keep future partitions in existence; the function cannot drop anything younger than one day, and its `retention_days` comes from the worker's configuration.

**usage_record**: `id`, `inference_request_id`, `provider_attempt_id unique null` (null only for the sweeper's record of an abandoned request), `tenant_id`, `provider_model_id null` (same exception), `model_price_id null`, `input_tokens null`, `cached_input_tokens null` (subset of `input_tokens`; null = not reported; always null unless `usage_source = reported`), `output_tokens null`, `usage_source text (reported|estimated|unavailable)`, `estimate_method text null` (e.g. `tokenizer:o200k_base`, `reservation_upper_bound`), `input_cost`, `output_cost`, `total_cost numeric`, `currency`, `recorded_at`
- Exactly one per Attempt that reached a Provider, including failed Attempts (an Attempt skipped for an open circuit has none). A failed Attempt has 0 tokens unless it was ambiguous. The sweeper's record for an abandoned request has no Attempt, NULL tokens and the whole held amount in `total_cost` (`input_cost` and `output_cost` stay 0).
- Index `(tenant_id, recorded_at)`.

**budget**: `tenant_id pk`, `limit_amount numeric`, `currency`, `updated_at`. The Tenant's standing monthly limit, owned by the Usage module (not `tenant_limits`) because the Reservation `UPDATE` consults it; no row means no Budget. Set through `IBudgets.SetMonthlyLimitAsync`, which the admin limits endpoint calls. It is read from the database at Reservation time, not from the configuration snapshot, so a change applies to the next request.

**budget_period**: `tenant_id`, `period_start date`, `limit_amount numeric null`, `reserved_amount numeric not null default 0`, `spent_amount numeric not null default 0`, `currency`, pk `(tenant_id, period_start)`
- `CHECK (reserved_amount >= 0)`
- Exists only for a month in which the Tenant had a Budget: created from `usage.budget` (with the month's held Reservations and Usage Records) when a Budget is set or by the month's first Reservation, and deleted for the current month when the Budget is removed. Invariant: `reserved_amount` = the Tenant's `held` Reservations of the month, `spent_amount` = the Usage Records of its requests that started in the month ([usage-and-budgets.md §3](usage-and-budgets.md#3-budget-enforcement-reservation-model)). The `BudgetPeriodOnlyWithBudget` migration deleted the rows earlier versions had created without a limit. `limit_amount` is still nullable but no longer written as NULL.

**reservation**: `id`, `inference_request_id unique`, `tenant_id`, `period_start`, `amount numeric`, `status (held|settled|expired)`, `expires_at`, `created_at` (= the request's `started_at`, which locates the partitioned request row), `settled_at null` (set when the Reservation is settled or expired). Index `(status, expires_at) where status = 'held'` (the sweeper) and `(settled_at) where status <> 'held'` (retention).

**usage_hourly** (rollup, written by the worker's `UsageRollupConsumer`): `tenant_id`, `provider_model_id`, `requested_alias`, `origin text check (api|evaluation)` (Request Origin), `hour timestamptz`, `requests`, `failed_requests`, `fallback_requests`, `attempts`, `input_tokens bigint`, `cached_input_tokens bigint` (null counted as 0), `output_tokens bigint`, `estimated_cost numeric`, `duration_ms_sum bigint`, `latency_histogram int[]` (fixed bucket bounds, so percentiles can be merged approximately), `ttft_histogram int[]`. pk `(tenant_id, provider_model_id, requested_alias, origin, hour)`, index `(hour)`. The `UsageHourlyOrigin` migration added `origin` to the key and backfilled existing rows as `api` (no Evaluation Run existed before it); the column has no default, because the rollup always writes it.
- A request lands in the UTC hour it **started** in, under the Provider Model that succeeded, else the last one called. A request that reached no Provider (routing failure, budget refusal, abandoned) uses the all-zero uuid as its `provider_model_id`.
- `failed_requests` counts `failed` and `abandoned`; `cancelled` is neither a success nor a failure. An abandoned request has no duration, so it adds nothing to `duration_ms_sum` or the histograms.
- Histogram bounds (ms, inclusive upper): 50, 100, 250, 500, 1 000, 2 500, 5 000, 10 000, 20 000, 30 000, 60 000, 120 000, plus one overflow bucket: 13 counts (`Usage.Domain.LatencyHistogram`). A percentile is estimated as the upper bound of the bucket that holds it.
- The `usage.request_completed` payload is `Usage.Domain.RequestCompletedEvent` (camelCase JSON): request, Tenant, alias, status, usage status, attributed and selected Provider Model, attempt count, had-fallback, input, cached-input and output tokens, Estimated Cost, currency, `startedAt`, `durationMs`, `ttftMs`, `origin`. Settlement and the sweeper copy `origin` from the request row. An event written before `origin` was added has no such member and is rolled up as `api`.

## `evaluation`

Owned by `ModelSwitch.Evaluation` (`EvaluationDbContext`, one EF migration history `evaluation.__ef_migrations_history`). There are no foreign keys to other schemas: `tenant_id` is checked against Identity (`ITenantDirectory`) when a Dataset or Prompt is created, and every query filters it by the caller's Tenant Grant in the application services. Every foreign key below is `ON DELETE CASCADE`, so deleting a Comparison, Dataset or Prompt removes everything under it. The application refuses to delete a Dataset or Prompt that a Comparison still uses, so in practice a Dataset delete never reaches a Comparison (see Retention).

**dataset**: `id`, `tenant_id`, `name`, `task_kind text check (extraction|classification|free_text)`, `latest_version int check (>= 0)` (0 until the first upload; moved only by `UPDATE … SET latest_version = latest_version + 1 … RETURNING`, whose row lock gives concurrent uploads distinct numbers), `created_at`. `unique(tenant_id, name)`, index `(tenant_id, id)`.

**dataset_version**: `dataset_id fk`, `version check (>= 1)`, `case_count check (>= 1)`, `content_sha256 text check (64 lower-case hex)` (canonicalization in [api.md](api.md#evaluation)), `scoring_schema jsonb` (`{taskKind, labels}` for classification, `{taskKind, fields}` for extraction, `{taskKind}` for free text), `created_at`, `created_by_admin_id null`. pk `(dataset_id, version)`. Append-only.

**eval_case**: `id`, `dataset_id`, `dataset_version` (fk to `dataset_version`), `external_id text` (from the JSONL), `input jsonb`, `expected jsonb`, `metadata jsonb null`, `ordinal int check (>= 0)` (position in the upload). `unique(dataset_id, dataset_version, external_id)`, `unique(dataset_id, dataset_version, ordinal)`. Append-only.

**prompt**: `id`, `tenant_id`, `name`, `latest_version int check (>= 0)` (moved like `dataset.latest_version`), `created_at`. `unique(tenant_id, name)`, index `(tenant_id, id)`.

**prompt_version**: `prompt_id fk`, `version check (>= 1)`, `template jsonb` (`{"messages":[{"role","content"}],"responseFormat"?}`, messages with `{{var}}`), `created_at`, `created_by_admin_id null`. pk `(prompt_id, version)`. Append-only.

**comparison**: `id`, `tenant_id`, `dataset_id`, `dataset_version` (fk to `dataset_version`), `name`, `created_at`, `created_by_admin_id null`. Index `(tenant_id, id)`.

**evaluation_run**: `id`, `comparison_id fk`, `tenant_id`, `dataset_id`, `dataset_version` (fk to `dataset_version`), `run_configuration jsonb` (`{dataset {id, version, contentSha256, taskKind}, target {alias, policyId, policyVersion} | {providerModelId, providerModel}, prompt {id, version, template}, params, evaluator {kind, version, config, judge?}, concurrency, gatewayVersion}`, [api.md](api.md#evaluation-runs-and-comparisons)), `config_sha256 check (64 lower-case hex)`, `max_estimated_cost numeric(20,10) null check (>= 0)` (USD), `status check (queued|running|succeeded|failed|cancelled)`, `cases_total`, `cases_done` (Case Results stored, any status), `cases_failed` (failed plus errored Case Results) (check `0 <= cases_failed <= cases_done <= cases_total`), `aggregates jsonb null`, `created_at`, `started_at null`, `completed_at null`, `error text null`. Indexes `(comparison_id)`, `(tenant_id, id)`, `(dataset_id, dataset_version)`.

**case_result**: `id`, `run_id fk`, `case_id fk` (to `eval_case`), `status check (passed|failed|errored|skipped)`, `score numeric(6,5) null check (0..1, and null when errored or skipped)`, `predicted jsonb null`, `output_text text null`, `score_details jsonb`, `inference_request_id uuid null`, `input_tokens null`, `output_tokens null`, `estimated_cost numeric(20,10) null` (these three are the candidate call only; null when no call was made; a failed call keeps its request id and the Estimated Cost its Usage Records recorded), `judge_inference_request_id uuid null`, `judge_input_tokens null`, `judge_output_tokens null`, `judge_estimated_cost null` (`llm_judge` only), `latency_ms null`, `error_code null`, `created_at`. `unique(run_id, case_id)`, which makes resuming idempotent; indexes `(case_id)`, `(inference_request_id)`, `(judge_inference_request_id) where not null` (the request detail page links back to the Case Result).

## Background processing (`jobs` schema, shared infrastructure)

**outbox_event**: `id`, `type`, `payload jsonb`, `occurred_at`, `published_at null`, `attempts`, `next_attempt_at null`, `last_error null`. Index `(published_at) where published_at is null`. Written through `SharedKernel.Outbox.OutboxWriter` in the writer's own transaction. Settlement and the sweeper append `usage.request_completed` with metadata only (ids, alias, status, tokens, cost). The relay (below) sets `published_at`; `attempts`, `next_attempt_at` and `last_error` record a consumer failure and its backoff.

**processed_event**: `consumer text`, `event_id uuid`, `processed_at`, pk both. This is the idempotency guard (NFR-06).

**job**: `id`, `kind`, `payload jsonb`, `status (pending|running|succeeded|dead)`, `attempts`, `max_attempts`, `run_after`, `locked_by text null`, `locked_until timestamptz null`, `last_error text null`, `dedupe_key text null` (unique where not null), `created_at`, `updated_at`. A failed attempt that will be retried goes back to `pending` with a later `run_after`, so there is no separate `failed` state.

All three tables are created by plain idempotent DDL in the Migrator (`SharedKernel.Jobs.JobsSchemaMigrator`; the `jobs` schema is shared infrastructure, owned by no module).

### How the worker uses them

- **Enqueue.** `IJobEnqueuer.EnqueueAsync(connection, transaction, request)` inserts in the caller's transaction, so the job exists only if the caller commits. `DedupeKey` makes a second enqueue a no-op, and `UniqueWhileActive` skips the enqueue while a job of that kind is pending or running.
- **Claim.** One `UPDATE ... WHERE id = (SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING` takes a job where `status='pending' and run_after<=now`, or `status='running' and locked_until<now and attempts<max_attempts` (the worker died). Claiming increments `attempts` and sets `locked_by` and `locked_until = now + LeaseDuration` (60 s). A `running` job whose lease expired on its last attempt is set to `dead` instead.
- **Heartbeat.** While the handler runs, the worker extends `locked_until` every 15 s. Every outcome update is guarded by `locked_by` and `attempts`, so a worker that lost its lease cannot overwrite the new owner. A lost lease cancels the handler's token.
- **Retry and dead-letter.** A handler exception sets `last_error` (exception type and a bounded message, never payload content) and the job returns to `pending` with `run_after = now + 5 s * 2^(attempts-1)` (cap 15 min). At `max_attempts` (default 5), or on `PermanentJobFailureException`, the job becomes `dead` and stays for inspection until retention removes it. A worker that is stopping hands its job back without spending an attempt.
- **Recurring jobs.** Each replica tries to insert the job for the current slot (`floor(now / interval)`) with `dedupe_key = kind@slot`. The unique index lets exactly one insert win, so a recurring job runs once per interval however many replicas exist. A slot missed while every worker was down is skipped. The Reservation sweeper is `usage.sweep_reservations`, every 30 s. `evaluation.sweep_orphaned_runs` (every minute) fails Evaluation Runs whose `evaluation.run` job was dead-lettered without the handler finishing them, and finalizes runs cancelled while running whose worker died before storing their aggregates ([evaluation.md §5](evaluation.md#5-execution)). A module reads a job's state only through `IJobStatusReader` (status by dedupe key), never by querying `jobs.job` itself.
- **Evaluation Runs.** `evaluation.run` (one per run, `dedupe_key = evaluation.run:<runId>`, payload `{"runId"}`) is enqueued by the api host in the transaction that creates the run; the worker's claim runs or resumes it ([evaluation.md §5](evaluation.md#5-execution)).
- **Outbox relay.** Per event, in one transaction: lock the oldest due unpublished event (`FOR UPDATE SKIP LOCKED`) whose type has a registered consumer, insert `(consumer, event_id)` into `processed_event` (a conflict means the consumer already ran), call the consumer on the same connection and transaction, then set `published_at`. A throwing consumer rolls the whole event back and delays it with the same exponential backoff, without blocking later events. Events with no registered consumer stay unpublished. The one consumer today is `usage.rollup` (`UsageRollupConsumer`, registered by `AddUsageModule`) for `usage.request_completed`.

## Retention

| Data | Default | Mechanism |
|---|---|---|
| `inference_request`, `provider_attempt` | 30 days (`Retention:RequestDays`) | Drop monthly partitions once fully expired, plus a daily batched delete for the boundary partition |
| `usage_record` | 400 days | Daily batched delete. Rollups are kept |
| `usage_hourly` | 400 days | Daily batched delete |
| `audit_record` | 400 days | Daily batched delete by a dedicated DB role |
| `outbox_event` (published), `processed_event` | 7 days | Daily |
| `job` (terminal) | 14 days | Daily |
| `reservation` (`settled` or `expired`) | `Retention:RequestDays` after `settled_at` (30 days) | Daily batched delete. `held` Reservations are never touched; the sweeper expires them |
| `administrator_session` | Until its sliding or absolute expiry | Daily batched delete (also on that Administrator's next sign-in) |
| Evaluation data (Datasets, Cases, Prompts, Comparisons, Evaluation Runs, Case Results) | Until an Operator deletes it | `DELETE` on the Dataset, Prompt or Comparison, cascading down the foreign keys (below) |

`usage_record` outlives the request rows it references, so its FK to `inference_request` is a soft reference: there is no DB-level FK, and the column is kept for correlation.

**The retention run** is the recurring worker job `retention.run`, once a day (`SharedKernel.Retention`). Each module contributes an `IRetentionTask` for its own tables (`usage`, `audit` and `sessions` from Identity, and `jobs` from the shared kernel); a task that fails is logged and the others still run. Every delete is batched (5 000 rows per statement, selected by primary key, so it is correct on partitioned tables). `usage` first calls `maintain_request_partitions(Retention:RequestDays, 12)`, then deletes the rows of the boundary partition older than the cutoff (`running` requests are kept). The job connects with `ConnectionStrings:PostgresRetention` (the `modelswitch_retention` role) when it is set; otherwise it runs as the app role, which cannot delete Audit Records, so `audit` removes nothing and a warning says which variable to set. `usage` also deletes `settled` and `expired` Reservations whose `settled_at` is older than the request cutoff, so a Reservation never outlives the request row it points to by more than a day; a `held` one is the sweeper's business and is never deleted. `sessions` deletes every `administrator_session` past its sliding or absolute expiry (such a session can never be used again).

**Evaluation data** is the one kind of user-provided content the gateway stores (ADR-0010), so it has no time-based retention: it stays until an Operator deletes it through the admin API ([api.md](api.md#evaluation), [evaluation.md §8](evaluation.md#8-deletion)). Deleting a Comparison removes its Evaluation Runs and their Case Results (model outputs included) and the Prompt template copied into each Run Configuration; deleting a Dataset removes its Dataset Versions and Cases; deleting a Prompt removes its Prompt Versions. A Dataset or Prompt that a Comparison still uses cannot be deleted (409 `conflict`), so content is removed Comparison first and nothing is left pointing at a missing Dataset or Prompt. Each delete writes an Audit Record with names and counts, never content. Inference Requests an Evaluation Run made keep only metadata (ADR-0010) and expire with the other request rows; once their run is deleted, their `evaluation_run_id` no longer resolves.

## Database roles (least privilege, NFR-03)

- `modelswitch_migrator`: owns the schemas and runs DDL. Used only by the migrator.
- `modelswitch_app`: DML on all module tables except `UPDATE`/`DELETE` on `audit_record`, `model_price`, `routing_policy_version`, `dataset_version`, `eval_case` and `prompt_version`. Used by api and worker. Deleting a `dataset` or `prompt` still removes its versions and Cases, because PostgreSQL runs `ON DELETE CASCADE` with the privileges of the referencing table's owner (the migrator role).
- `modelswitch_retention`: `DELETE` on retention-managed tables. Used only by the worker's retention job.

The migrator creates the runtime roles and re-applies these grants after every migration run ([deployment.md](deployment.md#4-database-initialization)). The EF migrations history table is not granted to `modelswitch_app`.
